## 3. APIs disponíveis (oficiais)

| Necessidade | API do Meta | Observação |
|---|---|---|
| Criar campanha / conjunto / anúncio | `POST act_{id}/campaigns`, `/adsets`, `/ads` | Exige **`ads_management`**. |
| **Validar sem criar** | parâmetro `execution_options=["validate_only"]` | É o botão **Validar campanha** (35.42) com a resposta real do Meta. |
| Confirmar o que foi criado | `GET {id}?fields=id,status,effective_status,…` | Releitura depois de cada criação (35.48). |
| Imagens | `POST act_{id}/adimages` | O Meta devolve um `hash`, que serve para não reenviar. |
| Vídeos | `POST act_{id}/advideos` em partes (start/transfer/finish) | Envio grande; ver risco 6.4. |
| Criativo | `POST act_{id}/adcreatives` | Página, Instagram, textos, CTA, link. |
| Públicos personalizados / semelhantes | `GET act_{id}/customaudiences`, `saved_audiences` | IDs reais da conta. |
| Interesses, comportamentos, locais | `GET /search?type=adinterest`, `adgeolocation`, `adTargetingCategory` | Busca oficial. |
| Estimativa de público | `GET act_{id}/delivery_estimate` | Opcional. |
| Pixels / datasets | `GET act_{id}/adspixels` | Cruza com o Tracking Engine. |
| Importar campanha existente como modelo | `GET campaign → adsets → ads → adcreatives` | 35.71/35.72. |
| Drive | **Google Drive API v3** (`files.list`, `files.get?alt=media`) | Somente leitura. |

**Transparência sobre "mostrar só opções que a API aceita" (35.3, 35.5, 35.12, 35.14):**
- O Meta **não tem** um endpoint que devolva a lista completa de objetivos × otimizações × janelas × posicionamentos válidos.
- **Listas reais da conta, lidas da API:** públicos, páginas, Instagram, pixels, interesses, locais e idiomas.
- **Regras de combinação:** ficam num **catálogo por versão da API** dentro do adaptador do Meta, montado a partir da documentação oficial.
  - Quando a Meta mudar, só esse catálogo muda, e ele pode ser trocado junto com a versão da API.
  - Nada fica espalhado pelas telas.
- **Garantia final:** antes de publicar, **sempre** roda o `validate_only` no Meta.
  - Se o catálogo estiver desatualizado, o Meta recusa na validação, e o sistema mostra o erro dele sem mudar nada sozinho.
- **Modo avançado:** um campo livre (JSON) para propriedades da API que o catálogo ainda não conhece, também validado pelo Meta.

## 4. Permissões necessárias

### No Meta (fora do CRM)
1. Token do **usuário do sistema** com **`ads_management`**. Hoje o CRM foi configurado para `ads_read` + `business_management`, ou seja, **só lê**.
2. O usuário do sistema precisa ter, na BM, as **contas de anúncio**, as **páginas** (permissão de criar anúncios) e os **perfis de Instagram** atribuídos.
3. O app do Meta provavelmente precisa de **acesso avançado** a `ads_management`, com revisão do app, para gerenciar contas de clientes. Isso depende de como o app e a BM estão montados. Confirmo na 35.1 lendo as permissões do token (`/me/permissions`) antes de liberar qualquer publicação.

### No Google (Drive)
- **Recomendação:** uma **conta de serviço** do Google com acesso **somente leitura** às pastas de criativos que você compartilhar com ela.
  - Não precisa de verificação do Google.
  - Não depende do login de ninguém.
  - Só vê o que você compartilhar.
- **Alternativa:** OAuth com o seu Google. O escopo de leitura do Drive é "restrito" e exige verificação do Google para uso fora do modo de teste.

### No CRM (novas, conforme 35.55)
- Hoje as permissões são **por papel**. O prompt pede **por pessoa** (criar, editar, publicar, modelos, criativos).
- **Proposta:** uma tabela de permissões do Campaign Builder **por usuário**.
  - Admin tem todas por padrão.
  - As demais permissões são marcadas pelo admin.
  - **Publicar** só com a permissão explícita **e** acesso ao cliente, conferidos no servidor (35.59).
- "Somente rascunho" (35.57) = pode criar, mas não publicar: envia para aprovação.

## 6. Riscos

1. **Dinheiro real:** publicar gasta verba.
   - Confirmação dupla com o resumo exato ("1 campanha, 3 conjuntos, 9 anúncios na conta X").
   - O campo **status** é obrigatório e não vem pré-preenchido: você escolhe Ativa ou Pausada.
2. **Permissão do Meta:** sem `ads_management` (e, se preciso, acesso avançado), nada é publicado. Esse é o bloqueio principal e depende de você na BM e no app.
3. **Publicação parcial e sem desfazer automático:**
   - O Meta cria objeto por objeto. Se o anúncio 2 falhar, a campanha e os conjuntos já existem.
   - O sistema mostra 🟡 parcial com o erro do Meta e a lista do que foi criado, e oferece **limpeza manual** (pausar ou excluir o que foi criado, com a sua confirmação).
   - Nunca tenta "consertar" a configuração sozinho.
4. **Vídeos grandes:**
   - As Edge Functions têm limite de tempo e memória. Vídeos são enviados em partes, em várias rodadas da fila.
   - Arquivos acima do limite do Meta são recusados **antes**, com o motivo.
5. **Mudanças da API do Meta:**
   - Versão em um só lugar, catálogo de regras por versão, `validate_only` sempre.
   - A v26.0 tem prazo de validade: a troca de versão fica como tarefa periódica.
6. **Limites de uso do Meta:** a publicação em lote é feita em fila, com limite configurável e espera progressiva.
7. **Categorias especiais** (crédito, emprego, moradia, política): o Meta restringe idade, gênero, raio e públicos semelhantes. O catálogo trava esses campos e o `validate_only` confirma.
8. **Duplicidade:** uma chave única por operação impede que um duplo clique, uma página recarregada ou um timeout criem a campanha duas vezes.
9. **Tamanho do trabalho:** são mais de 100 itens. Dividi em fases entregáveis e testáveis, cada uma com relatório.
