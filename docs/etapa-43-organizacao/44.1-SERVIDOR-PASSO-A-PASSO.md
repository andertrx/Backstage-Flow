# Servidor do WhatsApp (Evolution API) — passo a passo para o Ander

> Você só precisa fazer isto **uma vez**. Depende de você contratar o servidor; **eu acompanho cada passo** (mande o que aparecer na tela).
> Os arquivos prontos estão em `infra/whatsapp-evolution/` (`docker-compose.yml`, `Caddyfile`, `.env.example`).
> **Nunca mande por chat** a chave de acesso nem a senha do banco: elas ficam só no servidor e no campo do CRM.

## O que você vai ter no fim
Um servidor pequeno, ligado o dia todo, com um endereço seguro (ex.: `https://whats.backstageflow.com.br`), onde o seu chip fica conectado. O CRM conversa com ele para enviar os envios e os avisos. **O servidor não guarda mensagens, contatos nem conversas** (só a sessão do WhatsApp) e não avisa ninguém quando chega mensagem.

## Passo 1 — Contratar o servidor (VPS)
- Qualquer VPS com **Linux (Ubuntu 22.04 ou 24.04)**, **2 GB de memória**, 1 a 2 núcleos e 20 GB de disco. Serve o plano mais barato desse tamanho de qualquer provedor conhecido (confira o preço atual; costuma ser pouco por mês).
- Anote o **endereço de IP** do servidor e como entrar nele (o provedor tem um "console" no próprio site, sem instalar nada).

## Passo 2 — Criar o endereço (DNS)
- No **Registro.br** (onde está o seu domínio), crie um registro **tipo A** com o nome `whats` apontando para o **IP do servidor**. Resultado: `whats.backstageflow.com.br`.
- Pode levar alguns minutos para valer.

## Passo 3 — Instalar o Docker no servidor
No console do servidor, cole uma linha por vez:
```
curl -fsSL https://get.docker.com | sh
```
Conferir: `docker --version` deve mostrar um número.

## Passo 4 — Colocar os arquivos
```
mkdir -p ~/whatsapp && cd ~/whatsapp
nano docker-compose.yml
```
Cole o conteúdo do arquivo `docker-compose.yml` (que eu te mando pronto), salve (Ctrl+O, Enter, Ctrl+X). Repita para `Caddyfile`. Depois:
```
cp .env.example .env   # (crie o .env com o nano, colando o .env.example)
openssl rand -hex 24   # rode 2 vezes: uma gera a senha do banco, a outra a chave de acesso
nano .env              # preencha DOMAIN, POSTGRES_PASSWORD e AUTHENTICATION_API_KEY
```
**Anote a chave de acesso** (AUTHENTICATION_API_KEY) em local seguro: você vai colá-la no CRM.

## Passo 5 — Ligar
```
docker compose up -d
docker compose ps          # os 4 programas devem aparecer "running"
docker compose logs -f api # (Ctrl+C para sair) procure erros em vermelho
```
Abra `https://whats.backstageflow.com.br` no navegador: deve responder (o certificado seguro leva 1 a 2 minutos na primeira vez).

## Passo 6 — Conectar no CRM
1. **Configurações → Integrações → WhatsApp para envios automáticos**.
2. Endereço: `https://whats.backstageflow.com.br` · Instância: `backstage` · Chave: a do passo 4.
3. Marque **"Entendo o risco"** e **Salvar**.
4. **Conectar por QR Code** (ou digite o telefone do chip e **Gerar código**).
5. No celular do chip: **WhatsApp → Aparelhos conectados → Conectar um aparelho** e aponte para o QR Code (ou digite o código).
6. O CRM mostra **WhatsApp conectado**. Pronto.

## Segurança (rápido)
- No painel do provedor, deixe o firewall abrir só as portas **22, 80 e 443**.
- A porta do Evolution não é exposta (só o Caddy fala com ele).
- Troque a chave se achar que vazou (muda no `.env`, `docker compose up -d` de novo, e cola a nova no CRM).
- Faça **backup/snapshot** do servidor de vez em quando (o provedor oferece).
- Se o WhatsApp desconectar o aparelho, o CRM **desliga os envios sozinho**; basta conectar de novo.

## Se algo der errado
Mande a mensagem de erro (sem a chave). O que ainda não foi testado: este arquivo nunca rodou num servidor de verdade; os nomes das variáveis foram conferidos no código aberto do Evolution API. Se alguma configuração de privacidade (não guardar mensagens) atrapalhar o envio ou a lista de grupos, eu ajusto.
