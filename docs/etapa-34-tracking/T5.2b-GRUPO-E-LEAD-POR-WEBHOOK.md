# T5.2b — Link de grupo do WhatsApp e lead por webhook (Responde App) (08/11/2026)

Nenhum cliente real foi tocado. Tudo testado com avisos de exemplo.

## A. Link de grupo do WhatsApp (`chat.whatsapp.com`)
- O script do site passa a reconhecer o convite de grupo. O clique vira **Contato** com `canal = whatsapp_grupo` e a **origem da visita** (UTMs, IDs de campanha), igual ao clique no `wa.me`.
- **Sem código "(ref. …)":** o WhatsApp não aceita mensagem pronta em convite de grupo. O link não é alterado.
- Não duplica com o registro de cliques (`bf_click`).
- **Limite do WhatsApp:** dá para saber *que alguém clicou, vindo de qual campanha*; não dá para saber quem entrou no grupo.

## B. Lead por webhook (formulário de outro sistema, como o Responde App)
**Caminho:** o formulário guarda os parâmetros de URL (utm, fbclid, bf_c…) → ao enviar, o webhook do formulário avisa o CRM → o CRM cifra telefone/e-mail/nome, lê a origem, registra o **Lead** e manda ao Meta **pelo servidor**.

### Como configurar (Contatos → "Formulários de outros sistemas", admin e gestor)
1. Escolher o **site do Tracking** do cliente que recebe os leads e dar um nome. O CRM mostra o endereço (`…/functions/v1/lead-webhook?w=<id>`) e a **chave (uma vez só)**.
2. No formulário: cadastrar o webhook com o endereço e a chave (cabeçalho `x-webhook-key`, ou `&k=` no endereço) e **ligar "guardar parâmetros de URL"** mandando-os no webhook.
3. Enviar uma resposta de teste. O CRM mostra os **nomes dos campos** recebidos; "Sugerir pelos campos recebidos" preenche telefone, e-mail, nome e a origem (campos com o mesmo nome do parâmetro, ex.: `utm_source`).
4. Salvar o mapeamento, desmarcar **Modo teste** (o modo teste confere e mostra a origem lida, sem registrar nem avisar o Meta).

### Regras
- **Sem origem no aviso:** o lead entra **sem origem identificada** (nunca inventamos).
- **Telefone/e-mail/nome** chegam legíveis e são cifrados (SHA-256) no servidor; o corpo do aviso **nunca é guardado**, nem vai para log.
- **Não conta duas vezes:** mesma pessoa, mesmo formulário, mesmo dia = mesmo `event_id` (nem no Meta).
- **Pixel + servidor:** se o formulário também dispara o Pixel no navegador, o Meta pode contar o Lead duas vezes (o código de evento do Pixel não é o nosso). **Recomendado: mandar só pelo servidor** (não colar o Pixel no formulário).
- **Site que exige consentimento:** os avisos são **ignorados** (formulário de outro sistema não informa o consentimento). Trocar o site para "não exigir" só se o consentimento for coletado no formulário.
- Cliente desativado, site pausado ou endereço desligado: avisos ignorados (ficam no registro, sem dado pessoal).
- A página do formulário só vale se for do domínio do site; senão usa o domínio do site.
- Limite: 120 avisos por minuto por endereço; aviso maior que 64 KB é recusado.
