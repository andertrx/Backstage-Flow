# T5.3 — WhatsApp do cliente pelo servidor não oficial (08/11/2026)

Nenhum cliente real foi tocado. Testado com mensagens de exemplo. **Depende do servidor de WhatsApp (etapa 44), que ainda não está no ar.**

## O que faz
O número de WhatsApp do cliente fica ligado ao seu **servidor de conexão** (estilo Evolution API). A cada mensagem, o servidor avisa o CRM por webhook (`wa-inbound`). O CRM:
- **Mensagem recebida:** conta a conversa por número (cifrado), lê o **código "(ref. XXXXXX)"** do botão do site (liga a conversa à visita e à campanha) e a **origem do anúncio de WhatsApp** (`ctwaClid`, id do anúncio, endereço). Cria o Contato na ingestão normal, com a origem.
- **Mensagem enviada pela agência:** só é lida para achar as **frases de venda/etapa** do cliente (T4.1) e marcar o contato, com o valor da própria mensagem. Sem frase, nada sai.
- **Ignora:** grupos, listas de transmissão, status, outros eventos do servidor, mensagens sem número de telefone.
- **Nunca guarda o texto** da conversa (lido só na memória). O número vira hash SHA-256. Mensagem repetida não conta duas vezes.

## Como configurar (Tracking → Sites → "WhatsApp servidor", admin e gestor)
1. Informar o número do WhatsApp do cliente (com DDD). A conexão nasce **desligada** e o CRM mostra o **endereço** (`…/functions/v1/wa-inbound?c=<id>`) e a **chave (uma vez só)**.
2. No servidor de WhatsApp: cadastrar o webhook com o endereço e a chave (cabeçalho `x-webhook-key`, ou `&k=` no endereço), ligando só o evento de mensagens (`MESSAGES_UPSERT`), inclusive as enviadas por você.
3. Marcar **Ligado**. A situação passa a "aguardando mensagem" e, na primeira mensagem, "funcionando".
- Um site com WhatsApp pela API oficial não usa o servidor (e vice-versa). Um número não pode estar em dois sites.

## Limite importante (conta oficial)
Sem a conta oficial do WhatsApp (WABA), o Meta **não** recebe a venda como "anúncio de WhatsApp" (`business_messaging`): vai como **conversa** com o telefone cifrado. A origem do anúncio continua registrada no CRM. Para o formato completo é preciso a API oficial ou a Coexistence (T4.2).

## Formatos aceitos
Estilo Evolution API / Baileys: `messages.upsert` com `data.key.{remoteJid,fromMe,id}`, texto em `conversation`/`extendedTextMessage`/legendas, mensagens temporárias, `externalAdReply.{ctwaClid,sourceId,sourceType,sourceUrl}`, id "@lid" com telefone em `remoteJidAlt`/`senderPn`, hora em segundos ou milissegundos, lista de mensagens. **Servidores com outro formato podem precisar de ajuste** (o primeiro aviso real mostra).
