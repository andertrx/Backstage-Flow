# Etapa 34.5-W — WhatsApp (aplicativo comum)

> Status: **pronta**. Os clientes usam o **WhatsApp comum (app)**, não a API oficial.
> Remoção completa: `supabase/rollback/remover_tracking.sql` (já inclui esta fase).

## Como funciona

Sem a API oficial, o CRM **não consegue ler as conversas**. Por isso usamos um **código curto na mensagem**:

1. O visitante chega ao site, por exemplo por um anúncio do Meta. O script guarda a origem (34.1).
2. Ele clica no botão do WhatsApp do site. O script acrescenta ao fim da mensagem já escrita:
   `Olá! Quero saber mais (ref. K7Q2M9)`
3. O código fica ligado à visita, à origem e aos cookies do Meta (`_fbp`/`_fbc`) no momento do clique.
4. A mensagem chega no WhatsApp da empresa. A equipe abre **Tracking → WhatsApp**, digita o código e vê de onde a pessoa veio.
5. A equipe marca **Lead** ou **Venda** (valor, moeda, nº do pedido). Pode informar também o telefone, o e-mail ou o nome do cliente, que são **cifrados na própria tela** antes de sair.
6. A marcação vira um evento normal:
   - entra em leads, compras, jornada e receita (por moeda);
   - vai para o **Meta CAPI** como conversão de conversa (`action_source = chat`), com os cookies do clique. Assim o Meta liga a venda ao anúncio.

### Detalhes do código

- 6 letras/números, **sem 0, O, 1 e I** para não confundir (ex.: `K7Q2M9`).
- A busca aceita como vier: "ref. k7q-2m9", "K7Q2M9"…
- Um código novo a cada clique. Clicar de novo troca o código, não acumula dois.
- **É opcional:** só funciona com a opção "Código de rastreio no WhatsApp" marcada no código de instalação (`data-wa-code="1"`).
- **Sem a opção**, a mensagem do cliente não muda (o clique continua registrado como "Contato").
- **Marcar de novo não duplica:**
  - o Lead da mesma conversa conta uma vez só;
  - uma Venda com o mesmo nº de pedido é recusada.

## Tabela nova

| Tabela | Para quê | Campos principais | Retenção |
|---|---|---|---|
| `tracking_whatsapp_clicks` | Cada clique no WhatsApp com código | código, site, visita, origem no clique, `_fbp`/`_fbc`, situação (só clicou / lead / venda), nº de vendas, quem marcou e quando | Mesma do site (limpeza automática não ligada) |

Também mudou:
- `tracking_capi_queue.action_source` (novo campo): "website" ou "chat".

**O que a tela não vê** (garantido por permissão por coluna):
- o código do visitante e os cookies do Meta;
- ninguém altera cliques pela tela; as marcações passam pelo servidor.

## O que você precisa fazer

1. No código de instalação do site, marque **"Código de rastreio no WhatsApp"** e cole o código novo no site.
2. Combine com a equipe de atendimento:
   - ao receber uma mensagem com "(ref. …)", digitar o código em **Tracking → WhatsApp**;
   - marcar **Lead** quando for um contato de interesse;
   - marcar **Venda**, com valor e nº do pedido, quando fechar.
3. **Limites do WhatsApp comum** (só a API oficial resolveria):
   - se o cliente apagar o "(ref. …)" antes de enviar, ou chamar sem passar pelo botão do site, **não há como saber a origem**;
   - anúncios que abrem conversa direto no WhatsApp (Click-to-WhatsApp) também não trazem o código.

> Para clientes que usarem a **API oficial**, esses limites são resolvidos pela [Etapa 34.5-W2](34.5-W2-WHATSAPP-API.md).
