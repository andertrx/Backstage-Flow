# Etapa 34.5-W2 — WhatsApp pela API oficial (preparação)

> Status: **pronta e desligada**. Nada muda para quem usa o **WhatsApp comum (app)**: o código "ref." da 34.5-W continua igual.
> Ela só entra em ação num site em que alguém configurar a API oficial (botão **"WhatsApp API"** no card do site).
> Remoção completa: `supabase/rollback/remover_tracking.sql` (já inclui esta fase).

## Para que serve

Com a **API oficial do WhatsApp** (WhatsApp Business Platform / Cloud API), o Meta **avisa o CRM** a cada mensagem recebida no número da empresa (webhook).
Isso resolve os dois limites do app comum:

| Situação | App comum (34.5-W) | API oficial (34.5-W2) |
|---|---|---|
| Anúncio que abre conversa direto no WhatsApp (clique para o WhatsApp) | Origem desconhecida | Origem **confirmada**: o Meta manda o ID do anúncio e o `ctwa_clid` |
| Cliente veio pelo botão do site | Equipe digita o código | A conversa já chega ligada à visita do site (o código é lido sozinho) |
| Cliente chamou sem anúncio e sem botão | Nada registrado | Aparece como "Direto no WhatsApp" (sem inventar origem) |
| Marcar Lead/Venda | Pelo código | Pela conversa, na lista (botão "Marcar") |
| Envio ao Meta | `chat` | Anúncio de WhatsApp: **`business_messaging`** com `ctwa_clid` (o Meta liga a venda ao anúncio). Outras conversas: `chat` |

**O texto das mensagens nunca é guardado.** Do número do cliente, só o código SHA-256 (hash) — o mesmo formato que o Meta pede.

## Como funciona

1. No card do site → **WhatsApp API**: informa o ID do número de telefone, o ID da conta do WhatsApp Business (WABA) e o segredo do app do Meta.
2. O CRM gera um **endereço de webhook** e um **token de verificação** só para esse site.
3. Esses dois dados são colados no app do Meta (WhatsApp → Configuração → Webhook), assinando o campo **messages**.
4. A cada mensagem, o Meta chama o endereço. O CRM:
   - confere a **assinatura** do Meta com o segredo do app (aviso sem assinatura certa é recusado);
   - lê só: número (vira hash), hora, ID da mensagem (vira hash), código "(ref. …)" se houver, e os dados do anúncio se houver;
   - registra a conversa e a origem; aviso repetido pelo Meta não conta duas vezes.
5. A equipe vê a conversa em **Tracking → WhatsApp → Conversas recebidas** e marca Lead ou Venda.
6. A marcação vira evento normal (leads, compras, jornada, receita por moeda) e vai ao **Meta CAPI**.

## Tabelas novas

| Tabela | Para quê | Campos principais | Ligações | Retenção |
|---|---|---|---|---|
| `tracking_whatsapp_connections` | Número da API oficial ligado a um site (um por site) | ID do número, ID da conta (WABA), ligado/desligado, se tem segredo, última mensagem, último erro | site (`tracking_containers`) e cliente | Enquanto o site existir |
| `tracking_whatsapp_conversations` | Uma linha por cliente que mandou mensagem naquele número | hash do número, origem (anúncio de WhatsApp / botão do site / direto), ID do anúncio, `ctwa_clid`, código do site, nº de mensagens, primeira/última mensagem, situação (conversa/lead/venda), vendas, quem marcou | conexão, site, visita, origem (`tracking_touchpoints`), clique do site, lead | Mesma do site (limpeza automática **não** ligada) |

Índices: por cliente e data da última mensagem, por visita, por código do site, por origem e por lead. Uma conversa por número por conexão (sem duplicar).

Também mudou:
- `tracking_capi_queue`: aceita `business_messaging` e guarda `ctwa_clid` e o ID da conta (WABA).

**Segredos:** o segredo do app e o token de verificação ficam **só no cofre (Vault)**, nomes `wa_app:<id>` e `wa_verify:<id>`. A tela nunca recebe o segredo de volta; o token de verificação só aparece para admin/gestor, ao clicar em "Ver endereço do webhook".

**O que a tela não vê** (permissão por coluna): hash do número, `ctwa_clid`, visita, e as referências do cofre. Ninguém grava nessas tabelas pela tela.

## O que você precisa fazer (só quando um cliente usar a API oficial)

1. No [developers.facebook.com](https://developers.facebook.com) → app do cliente → **WhatsApp → Configuração da API**: copie o **ID do número de telefone** e o **ID da conta do WhatsApp Business**.
2. Em **Configurações do app → Básico**: copie a **Chave secreta do app**.
3. No CRM: **Tracking → card do site → WhatsApp API**. Cole os três dados e salve.
4. Clique em **Ver endereço do webhook**.
5. No app do Meta: **WhatsApp → Configuração → Webhook → Editar**. Cole a URL e o token de verificação → **Verificar e salvar**. Depois assine o campo **messages**.
6. Volte ao CRM, marque **Registrar as conversas** e salve. Mande uma mensagem de teste ao número: ela aparece em "Conversas recebidas".
7. Para o envio ao Meta funcionar, o site precisa do **Meta CAPI** configurado (34.3) com os eventos Lead/Compra ligados.

**Atenção:** se o número usar um provedor (BSP) que já recebe o webhook, o Meta só manda para um endereço por app — combine com o provedor antes.
