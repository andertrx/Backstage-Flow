# Etapa 40.4 — MCP no Comercial (leads) e nas Reuniões

**Data:** 27/10/2026. **Pedido do Ander:** "pode", depois do relatório da 40.3. Isso aprovou o plano combinado: 40.4 = Comercial + Reuniões, e os contatos dos leads ficam escondidos da IA.

## 1. O que mudou
- O servidor MCP passou para a **versão 1.3.0**, com 56 ferramentas para o administrador (35 delas mudam algo).
- Agora o Claude também cuida dos **leads do Comercial** e das **reuniões da Central**.
- Ele usa as mesmas ações e permissões do site, e tudo fica no histórico como "via MCP".

## 2. Ferramentas novas — Comercial (só quem tem "Comercial" na Central, e o administrador)
| Ferramenta | O que faz |
|---|---|
| `backstage_commercial_reference` | Etapas do funil (aberto, ganho, perdido) e motivos de perda, com os IDs |
| `backstage_list_leads` | Lista os leads, com filtros: busca, responsável, origem, prioridade, atrasados, arquivados, etapa |
| `backstage_get_lead` | Abre um lead: dados, etapa, próxima ação, **versão** e histórico de interações |
| `backstage_save_lead` | Cria um lead, ou edita só os campos enviados. Avisa possíveis duplicados |
| `backstage_move_lead` | Muda a etapa. Para "perdido", pede o motivo da perda |
| `backstage_lead_note` | Registra uma interação: contato, reunião, proposta, contrato ou observação |
| `backstage_archive_lead` | Arquiva ou desarquiva o lead (nada é apagado) |

**Contatos dos leads:**
- **Quais são:** nome do contato, telefone, e-mail e CNPJ.
- **O que o Claude faz:** **grava** quando você dita, mas **nunca recebe de volta**. A resposta diz só se cada um está "cadastrado: sim/não".
- **Ao editar:** o servidor mantém os contatos que já existiam sem mostrá-los à IA.
- **No histórico:** os contatos já aparecem só como "alterado", como no site.
- **Converter lead em cliente:** continua **só pelo site**, porque mexe no cadastro de clientes.

## 3. Ferramentas novas — Reuniões (quem acessa a Central; o banco confere quem organiza)
| Ferramenta | O que faz |
|---|---|
| `backstage_meeting_reference` | Tipos de reunião (daily, setor, cliente, planejamento…) |
| `backstage_list_meetings` | Lista reuniões, com filtros: período, tipo, setor, cliente, situação, pessoa, só as minhas, busca |
| `backstage_get_meeting` | Abre a reunião: pauta, ata, participantes e presença, itens, tarefas geradas, histórico e versão |
| `backstage_save_meeting` | Agenda uma reunião, ou edita só os campos enviados (mantém os participantes se você não mandar outros) |
| `backstage_record_meeting` | Marca como realizada, com ata e presença (ou corrige a ata) |
| `backstage_meeting_add_item` | Adiciona objetivo, pendência, decisão ou bloqueio |
| `backstage_meeting_item_to_task` | Transforma uma pendência ou bloqueio em tarefa da Central (precisa de "criar tarefas") |
| `backstage_cancel_meeting` | Cancela uma reunião agendada, com motivo. Ela continua no histórico |

**Ficaram de fora de propósito:** "remover item da reunião" (é uma remoção) e as configurações do Comercial e das Reuniões (etapas, motivos, tipos). Essas continuam no site.

## 4. Banco de dados
**Nenhuma mudança no banco e nenhuma tabela nova.**
- O MCP chama as mesmas funções do site (`ops_lead_*` e `ops_meeting_*`), da lista fechada em `data.ts`.
- A marca "via MCP" vem dos gatilhos da 40.3.
