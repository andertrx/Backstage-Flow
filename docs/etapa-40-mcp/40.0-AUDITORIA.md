# Etapa 40.0 — Auditoria para o servidor MCP (26/10/2026)

Feita só com leitura (código, banco e documentação oficial do Supabase), antes de qualquer mudança.

## Arquitetura atual
- **Site:** React 19 + Vite + TypeScript (Tailwind, TanStack Query, React Router), estático na Vercel. Não há servidor Node próprio.
- **"Back-end":** Supabase — Postgres com RLS em todas as tabelas, funções do banco (RPC) e 15 Edge Functions em Deno.
- **Login:** Supabase Auth (e-mail e senha); assinatura dos tokens ES256 com chave pública (JWKS) — bom para OAuth.
- **Papéis:** admin, gestor, operador, visualizador, equipe, cliente, vendedor (`public.user_role`), lidos do banco.
- **Isolamento entre clientes:** no banco (`private.visible_client_ids()` / `can_view_client` nas políticas RLS).
- **Consultas reaproveitáveis (respeitam o RLS, security invoker):** `metrics_summary`, `dashboard_summary`, `campaign_table`, `account_balances`, `monitor_alerts_query`.
- **Logs:** `audit_logs`, `error_logs` (com remoção de segredos), `sync_runs`. **Limite de chamadas:** `rate_limit_hit` (só servidor).
- **Dados reais na data:** 30 clientes, 35 contas, 1.397 campanhas; 1 admin e 2 visualizadores.
- **SDK oficial do MCP (TypeScript):** compatível com o Edge Runtime (transporte HTTP "streamable" padrão Web). Guia oficial do Supabase: "Deploy MCP servers".
- **OAuth 2.1 do Supabase:** existe (beta) e foi feito para MCP; no projeto estava **desligado** ("OAuth server is disabled").

## Decisões
- Servidor **remoto** (Edge Function `mcp`), só leitura, com o login de cada pessoa (OAuth do Supabase) e as consultas existentes — sem chave administrativa para dados e sem acesso direto ao banco.
- MCP local (STDIO) não implementado: exigiria guardar credencial no computador e o Ander não trabalha localmente.
- Papéis cliente e vendedor bloqueados na primeira versão. Registro das chamadas por 180 dias (Ander).
- Número da etapa: 40 (38 e 39 já existiam).

## Achado durante a implementação
O Supabase retira o cabeçalho `WWW-Authenticate` das respostas das Edge Functions. Solução: endereço público no domínio do site (`https://www.backstageflow.com.br/mcp`, repassado pela Vercel) e arquivo de descoberta `/.well-known/oauth-protected-resource/mcp` publicado pelo site — caminho previsto na especificação do MCP.
