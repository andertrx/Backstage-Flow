# Etapa 40.2 — MCP com escrita na Central de Operações

**Data:** 26/10/2026. **Pedido do Ander:** "meu MCP, que já está conectado, consiga mexer dentro do meu CRM (não no Meta): criar tarefa, mexer nessas configurações do sistema". Respondeu "pode" à proposta; segui as recomendações: **tarefas + configurações da Central**, com **as mesmas permissões que cada pessoa já tem no site**.

## 1. O que mudou
O servidor MCP (versão **1.1.0**) agora também **faz** coisas na Central de Operações, além de consultar. Ele chama **as mesmas ações do site**, com o login da pessoa: o banco confere a permissão e grava o histórico de sempre (linha do tempo da tarefa e registro de auditoria). Nada é apagado: arquivar e desativar podem ser desfeitos.

## 2. Ferramentas novas
**Para enxergar (só leitura):**
| Ferramenta | O que faz |
|---|---|
| `backstage_central_reference` | Setores, status (com o grupo), colunas das filas, tipos de atividade, pessoas, clientes e as suas permissões na Central — os IDs para criar/editar |
| `backstage_list_tasks` | Lista tarefas com filtros (busca, cliente, setor, status, grupo, prioridade, pessoa, só as minhas, atrasadas/hoje/semana/sem prazo, arquivadas) |
| `backstage_get_task` | Abre uma tarefa (descrição, pessoas, etiquetas, dependências, últimos comentários, **versão**) |

**Para mexer (o Claude pede "Permitir?" antes de cada uma):**
| Ferramenta | O que faz | Quem pode (permissão da Central) |
|---|---|---|
| `backstage_create_task` | Cria tarefa (título, setor, cliente, descrição, prioridade, início, prazo, horas, visibilidade, etiquetas, status, responsável, adicionais) | criar tarefas |
| `backstage_update_task` | Edita só os campos enviados; recusa se alguém mudou a tarefa depois da leitura | editar tarefas |
| `backstage_set_task_status` | Muda o status (respeita dependências e regras do quadro) | mover cartões ou editar |
| `backstage_set_task_people` | Define responsável e adicionais (mantém aprovadores e observadores) | atribuir pessoas |
| `backstage_comment_task` | Comenta, com menções (avisam no sino) | quem acessa a Central |
| `backstage_archive_task` | Arquiva ou desarquiva | arquivar |
| `backstage_save_sector` / `backstage_set_sector_status` | Cria/renomeia setor; ativa, desativa ou arquiva (movendo as pessoas) | **só administrador** |
| `backstage_save_status` / `backstage_set_status_active` | Cria/edita status de tarefa; ativa ou desativa (movendo as tarefas) | **só administrador** |
| `backstage_save_queue_column` / `backstage_set_queue_column_active` | Colunas da fila de cada setor | **só administrador** |
| `backstage_save_activity_type` | Tipos de atividade | **só administrador** |

As ferramentas aparecem para cada pessoa conforme as permissões dela; mesmo que alguém tente, o banco recusa o que a pessoa não pode fazer no site.

## 3. O que continua proibido
Apagar qualquer coisa; mexer em clientes, usuários, permissões, integrações, tokens, saldos, campanhas, orçamentos, Meta ou Google; SQL ou comandos livres; ler arquivos.

## 4. Segurança
- Escritas marcadas como "não só leitura" (o Claude pede confirmação); desativar/arquivar marcadas como ação de maior efeito.
- Lista fechada de ações permitidas no servidor (`OPS_RPCS` em `data.ts`); qualquer outra é recusada.
- Conflito de versão: edição recusada se a tarefa mudou desde a leitura ("Alguém alterou esta tarefa…").
- Mensagens do banco viram mensagens claras (sem permissão, valor inválido, já existe, escolha para onde mover).
- Cada chamada continua no registro do MCP (180 dias) e no limite de 60 por minuto.
