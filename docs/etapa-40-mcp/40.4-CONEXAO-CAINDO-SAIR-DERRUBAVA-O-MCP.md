# 40.4 — Correção: a conexão do Claude (MCP) caía toda hora

## O que acontecia
O botão **Sair** do CRM chamava `supabase.auth.signOut()` sem opção. Nesse caso o Supabase encerra **todas as sessões do usuário** (padrão "global"), incluindo a sessão que o Claude usa no MCP. Resultado: cada vez que alguém saía do CRM (ou o navegador pedia a saída), o MCP perdia o login e a conexão caía ("Login expirado ou inválido").

## Como foi achado (09/11/2026)
- O servidor `mcp` estava saudável (sem erros próprios, resposta em ~0,4 s).
- Nos registros de login do Supabase: às 12:51 o Claude tentou renovar o login e recebeu "Refresh Token Not Found"; entre 06:42 e 06:48 houve vários "Session not found" do MCP e um `/logout` do site às 06:48. Só havia 2 sessões no banco (as anteriores tinham sumido).
- Nada no CRM nem no agendador do banco apaga sessões; o plano do Supabase é gratuito, que não tem limite de uma sessão por usuário nem expiração por inatividade. Então a causa estava no próprio "Sair".

## O que mudou
`AuthProvider.tsx`: `signOut({ scope: "local" })`. Sair agora encerra só a sessão **deste navegador**; o MCP e os outros aparelhos continuam logados.

## O que continua normal
- O login do MCP dura 1 hora e o Claude renova sozinho enquanto a sessão existir. Isso não é queda.
- Mudar a senha ou "esqueci minha senha" ainda podem encerrar outras sessões (comportamento do Supabase).
- Se a sessão do MCP já tinha sido derrubada antes desta correção, é preciso reconectar uma vez: `/mcp` → backstage-flow → Re-authenticate.

## Não testado
Não consegui reproduzir a queda real do MCP aqui. A correção está confirmada pelo código e pelos registros; só o uso dos próximos dias mostra se parou de cair.
