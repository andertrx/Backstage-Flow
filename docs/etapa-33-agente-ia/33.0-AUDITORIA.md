## 1. Como o sistema é hoje (fotografia)

| **Login e papéis** | Supabase Auth + `profiles.role`: admin, gestor, operador, visualizador, cliente. Matriz de permissões na Etapa 20. Hoje: 1 admin e 2 visualizadores. |
| **Clientes** | `public.clients` (28), com fuso horário próprio. |
| **Contas de anúncio** | `public.ad_accounts`, ligadas a `platform_connections` (token no Vault). Hoje: **28 contas Meta**, **0 Google** (Google ainda não conectado). |
| **Campanhas / conjuntos / anúncios** | `public.campaigns`, `ad_groups` e `ads` (1.351 / 2.825 / 15.433). Hoje: 78 campanhas ativas. |
| **Métricas históricas** | `public.metrics_daily`, particionada por mês, com 144 mil linhas desde 01/09/2025, nos níveis conta, campanha, conjunto e anúncio. Índices "resumo" da Etapa 30. Alcance por período em `period_reach`. |
| **Saldo e status** | `account_snapshots`: fotografias de saldo e status a cada sincronização. |

| **Alertas** | `public.alerts` + `refresh_alerts()` a cada 15 min (`pg_cron`). Tipos: sem saldo, saldo baixo, conta restrita/desativada, pagamento pendente, problema de cobrança, sem forma de pagamento, sincronização atrasada, erro de API, campanha sem entrega, queda de resultados. |
| **Logs** | `audit_logs` (quem fez o quê), `sync_runs` e `error_logs` (erros técnicos sem segredos). |
| **Proteções** | Limite de requisições (`rate_limit_hit`), CORS restrito, CSP e varredura de segredos (Etapa 26). |
| **Plataformas** | Catálogo único e adaptadores por plataforma (Etapa 28). |
| **Notificações** | Só dentro do sistema (sino de alertas). Não há e-mail nem push. |

### Respostas às perguntas do prompt
1. **Clientes:** `clients`.
2. **Contas:** `ad_accounts`.
3. **Campanhas:** `campaigns`, `ad_groups`, `ads`.
4. **Métricas históricas:** `metrics_daily`, `period_reach`, `account_snapshots`.
5. **Sincronização:** cron → Edge Function `sync` → adaptador Meta/Google → `ingest_metrics_daily`.
6. **Identificação da conta:** `platform_id` + `external_id` (ex.: `meta` + `123…`), mais a conexão com o token no Vault.
7. **Ações para Meta e Google:** **hoje não existem.** O sistema só lê. Ver a seção 4.
8. **O que reaproveitar:** a lista está na seção 2.
9. **O que criar:** a lista está na seção 3.
10. **Agendamento sem duplicar infraestrutura:** o mesmo esquema da sincronização (cron → Edge Function), com trava por conta.
11. **Controle de consumo de IA:** conferir o limite antes de cada chamada; tokens reais lidos da resposta da API.
12. **Registro de custo e tokens:** tabela de uso, uma linha por chamada (seção 3).

## 4. Pontos de atenção encontrados

1. **Google Ads não está conectado.** O agente começa pelo Meta. O Google entra quando a conexão existir, porque o código é o mesmo, pelo catálogo de plataformas.
2. **Escrita no Meta (fases 33.5 a 33.8).**
   - A conexão atual foi feita para leitura. Alterar orçamento ou pausar exige o token do usuário do sistema com a permissão **`ads_management`**. Em geral o app também precisa de **acesso avançado** aprovado pela Meta.
   - Vou conferir as permissões do token no início da 33.5, sem mexer em nada.
   - As fases 33.1 a 33.4 **não dependem disso**.
3. **Chave da IA.**
   - É preciso criar uma chave em **console.anthropic.com** (conta da Anthropic, com cartão) e colocá-la nos **segredos das Edge Functions** do Supabase, com o nome `ANTHROPIC_API_KEY`.
   - Eu não consigo criar essa chave por você. Ela nunca vai para o site nem para o código.
4. **Preço da IA é em dólar.**
   - O custo é registrado em US$ e convertido para R$ por uma **cotação que você configura**.
   - A tela mostra "convertido pela cotação X", conforme a regra de moeda do projeto.
5. **Dia de hoje é parcial.** Decisões usam dias fechados; o dia de hoje só serve para alertas.
6. **Dados enviados à IA.**
   - Vão só números agregados, nomes e status de campanhas e contas.
   - Não vão dados pessoais nem tokens. O sistema não guarda dados de leads.
7. **Servidor do banco é pequeno** (~1 GB). As análises usam as consultas já otimizadas na Etapa 30, e o agente roda uma conta de cada vez, com trava, para não pesar na sincronização.

## 5. IA: modelo, formato e custo estimado

- **Provedor:** Anthropic (Claude), pela **API oficial** e SDK oficial, chamada só pela Edge Function.
- **Modelo padrão:** Claude Opus 5 ($5 por milhão de tokens de entrada e $25 por milhão de saída).
  - Opção mais barata: Claude Sonnet 5 ($2 / $10), cerca de 60% menos.
  - O modelo fica **configurável** na tela do agente. Você escolhe.
- **Economia:**
  - regras antes da IA;
  - uma chamada por execução com **só os casos suspeitos de cada conta**;
  - resumo em vez de histórico completo;
  - *prompt caching* das instruções fixas;
  - reaproveitar a análise se os dados da conta não mudaram.
- **Custo estimado.** São estimativas; os valores reais serão medidos na 33.3 e aparecerão na tela. A cotação usada é **R$ 5,50 = US$ 1** só para esta conta.

| Cenário | Chamadas/dia | Tokens por chamada (entrada + saída) | Custo/dia (Opus 5) | Custo/mês (Opus 5) | Custo/mês (Sonnet 5) |
|---|---|---|---|---|---|
| 28 contas, 2x/dia, ~5 contas com casos por execução | ~10 | ~12 mil + 2 mil | ≈ US$ 1,10 (≈ R$ 6) | ≈ R$ 180 | ≈ R$ 70 |
| Idem, só 1x/dia | ~5 | idem | ≈ R$ 3 | ≈ R$ 90 | ≈ R$ 35 |
| Só "Analisar agora" (manual) | conforme uso | idem | ≈ R$ 0,60 por análise de conta | — | ≈ R$ 0,25 por análise |

Com a sugestão de limite de R$ 100/mês:
- no **Sonnet 5**, cabe o cenário de 2x/dia;
- no **Opus 5**, cabe o cenário de 1x/dia.

O limite nunca é ultrapassado: ao chegar nele, a IA pausa e as regras continuam.
